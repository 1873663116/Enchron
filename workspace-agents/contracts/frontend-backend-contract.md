# Enchron Frontend/Backend Contract

## 1. 文档定位

这不是一份接口明细手册，而是一份规范性契约。

本文中的“前端 / 后端”默认指协作分工，而不是部署形态：

- 前端 = UI、交互、呈现
- 后端 = 客户端内部逻辑、远程数据访问抽象、接口契约

它回答的是：

- 前端和后端分别负责什么
- 哪些能力允许本地实现，哪些能力应通过远程契约表达
- 协作时谁先改什么
- 什么样的变更算契约变更

它不负责逐字段定义请求 / 响应结构；这些内容放在同目录下的 `openapi.yaml`。

## 2. 当前项目形态

Enchron 当前不是经典的前后端分离系统，而是一个 visionOS 客户端，内部带有清晰的模块边界。

当前远程 SMB / WebDAV 访问仍在客户端内完成，但这不改变一个事实：

- 只要存在“UI 层”与“远程数据访问层”的稳定边界，就需要维护一份前后端契约

这里的“后端”可以是未来独立服务，也可以是当前客户端内部被抽象出来的逻辑 / 数据访问层。契约的作用是约束边界，而不是假设部署形态已经完成。

## 3. 契约与 API 参考的关系

同目录下有两类文件，职责不同：

- `frontend-backend-contract.md`
  规范性文件，定义边界、职责、协作规则、版本策略
- `openapi.yaml`
  具体 API 参考，定义 endpoint、schema、错误模型、示例结构

二者必须一起维护，但不能互相替代。

## 4. 职责边界

前端负责：

- visionOS UI 与交互
- 播放控制界面与信息展示
- 窗口 / 沉浸 / 全景的用户可见呈现与交互
- 本地文件与 Photo Library 的用户入口、授权流程与选择交互
- 页面状态编排，以及对后端提供数据的消费与展示

后端负责：

- 客户端内部的业务逻辑与接口契约设计
- 远程数据源注册与连接校验
- SMB share 发现与选择
- 远程文件 / 文件夹浏览
- 可播放 URL 解析或下发
- 远程媒体元数据探测
- 播放进度同步
- 为前端提供稳定的读模型、错误语义和状态边界

明确例外：

- `local`
- `photoLibrary`

这两类来源默认属于前端本地职责，不进入远程 API 契约。

## 5. 协作默认流程

团队默认按下面顺序协作：

1. 先更新契约
2. 再改实现
3. 前端以契约和 examples 为 mock 基准
4. 后端按相同 schema 和错误语义落地
5. 字段语义变化必须与契约更新处于同一变更集

禁止出现以下情况：

- 前端私自扩展一个字段语义但不改契约
- 后端返回了新结构但不改契约
- 前后端任一方绕过契约形成隐式约定

## 6. 什么算契约变更

以下任一情况都属于契约变更：

- 新增或删除 endpoint
- 请求 / 响应字段新增、删除、重命名
- 字段含义变化
- 错误码、错误结构、错误语义变化
- 交互流程变化，例如 SMB 连接从“先 host 后 share”改成别的顺序
- 版本策略变化

出现这些变化时，必须同步更新 `openapi.yaml`。如果同时影响职责边界或协作方式，也必须同步更新本文件。

## 7. 变更策略

- 优先做增量变更：新增字段优于删除或重命名字段
- 破坏性变更必须显式版本化，例如 `/v2/...`
- 密码、token、密钥等敏感字段必须是 write-only，不得出现在响应中
- examples 必须与当前契约一致，不能成为过期样例

## 8. 事实来源

关于“怎么协作、边界在哪、变更何时算越界”，以本文件为准。

关于“字段长什么样、错误结构是什么、payload 长什么样”，以 `openapi.yaml` 和 `examples/` 为准。
