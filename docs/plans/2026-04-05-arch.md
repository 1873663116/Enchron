## Technical Issues

### P1-1: RecentlyPlayedView Module Boundary Violation (FIXED)

**Problem:** Unit 5 placed RecentlyPlayedView in `XrPlayer/PlayerUI/Views/`. ARCHITECTURE.md defines PlayerUI as "播放界面与模式决策" — RecentlyPlayedView is content browsing, not playback UI.

**Blast radius:** Wrong module placement creates precedent for dumping browsing concerns into PlayerUI. Violates Architecture Invariant: modules have explicit bounded responsibilities.

**Fix applied:** Moved to `XrPlayer/App/Views/RecentlyPlayedView.swift`. App module owns navigation-level assembly. RecentlyPlayedView is a top-level navigation target (like SettingsView), not a PlayerUI component.

### P1-2: ScreenPositionControlView Deletion Without Replacement (FIXED)

**Problem:** Unit 12 deleted ScreenPositionControlView.swift, claiming "replaced by system Menu." But ScreenPositionControlView has continuous sliders (Distance: 2.0-20.0m, Vertical Offset: -2.0-2.0m, View Angle: -45° to 45°). System Menu supports only discrete Picker items, not continuous sliders. This would silently remove immersive cinema screen positioning.

**Blast radius:** Loss of immersive mode screen position adjustment. Users cannot fine-tune virtual screen distance, height, and angle. This is core cinema experience functionality (REG-100~107).

**Fix applied:** Changed to restyle instead of delete. ScreenPositionControlView gets design token updates (colors, glass effects) like DataSourceConfigView in Unit 11. Continuous sliders preserved.

### P1-3: Companion WindowGroup Incomplete Environment Injection (FIXED)

**Problem:** Unit 13 said "Inject same environment objects" without enumerating all 5. PlayerControlsView requires: AppModel, WindowVideoViewModel, FileBrowsingViewModel, PlaybackLaunchCoordinator, PanoramaLayerBridge. Missing any one causes @Environment crash at runtime.

**Blast radius:** Companion window would crash on first access if any environment missing.

**Fix applied:** Added explicit 5-item environment injection list to Unit 13, referencing main WindowGroup pattern (XrPlayerApp.swift:124-131).

### P1-4: PlaybackLaunchRequest Missing Identifiable Conformance (FIXED)

**Problem:** Unit 10 uses `.sheet(item: $viewModel.detailNavigationRequest)` where detailNavigationRequest is `PlaybackLaunchRequest?`. SwiftUI's `.sheet(item:)` requires the type to conform to `Identifiable`. PlaybackLaunchRequest likely doesn't.

**Blast radius:** Compilation failure at Unit 10 integration.

**Fix applied:** Added prerequisite note to Unit 10: PlaybackLaunchRequest must conform to Identifiable (add UUID id property or derive from fileIdentifier).

### P2-1: Auto-Hide Timing Behavioral Change (Noted)

Current MainView auto-hide uses 3-second timeout. Plan R24 specifies 5 seconds. This is intentional per design spec, not accidental. Noted for awareness.

### P2-2: Precision Timeline During Slider Drag

PlayerControlsView lines 161-176 show a detailed precision timeline that appears during slider drag (orange color, precise time format with frames). Unit 12's redesign must preserve this UX pattern. The existing `DetailedTimelineView` is separate from the NLE timeline (Phase E). Both must coexist: precision view during slider drag (embedded in control bar) + NLE timeline (expandable panel).

### P2-3: Filter Pills Data Availability

Unit 8 adds filters (4K/HDR/Spatial) based on MediaProfile characteristics. The deferred question "Need to verify MediaProfile field availability for 4K/HDR/Spatial detection" is a real risk. FileBrowsingDomain.MediaFile may not carry resolution/HDR metadata. If unavailable, filter pills degrade to non-functional. Mitigation: fall back to filename-based heuristic detection during implementation.

## Architecture Recommendations

### Navigation State Flow (Validated)

```
BEFORE:                          AFTER:
AppTabView (TabView)             NavigationOrnament (.ornament)
  owns tab selection               reads AppModel.selectedTab
  via internal @State               writes AppModel.selectedTab

MainView                         MainView
  contains AppTabView               ornament(leading): NavigationOrnament
  no knowledge of tabs               switch(selectedTab): conditional content
                                     ornament(bottom): PlayerControlsView
```

This is architecturally clean. Navigation state moves from View-owned (@State inside TabView) to Model-owned (AppModel.selectedTab). Aligns with Architecture Invariant: "没有把业务状态机默认塞进 SwiftUI View."

### File Browser Transformation (Validated)

```
BEFORE:                          AFTER:
NavigationStack                  NavigationSplitView
  VStack                           sidebar: FileBrowserSidebar
    ActiveDataSource bar              List(selection:) with Sources
    SavedSources scroll             detail: VStack
    NavigateUp button                   BreadcrumbView
    FolderListView                      FilterPillsView
      navigationDestination →           ContentGridView (LazyVGrid)
        VideoDetailView                   .sheet: VideoDetailView
```

Clean separation. Sidebar and detail columns map naturally to existing ViewModel properties (savedDataSources, files).

### Companion Window Lifecycle (Risk Area)

```
Trigger: appModel.playbackMode != .window && appModel.isPlaying
  → openWindow(id: "playerControls")

Dismiss: exit immersive OR stop playback
  → dismissWindow(id: "playerControls")

Edge case: user manually closes companion window
  → need .onDisappear detection to set flag
  → re-open on next mode change? Or let user tap to reopen?
```

The plan acknowledges this edge case ("User manually closes companion window → recoverable") but doesn't specify mechanism. Implementation should use `.onChange(of:)` on a `@State` flag or detect via scene phase. Not blocking, but needs attention during Unit 13 implementation.
