# 0001 — 协作宪法：人类-agent 协作的文档与工作机制

- Status: 已采纳
- Date: 2026-06-10

## 背景

单人维护者（产品角色、新手工程认知）+ 多 agent 会话（mac 本地 + 云端）协作开发。双方都健忘：agent 跨会话彻底失忆，人类跨周丢失细节。文档此前按惯例自由生长，实测后果：

- `AGENTS.md` 与 `CLAUDE.md` 作为平行副本，一轮会话内漂移 27 行（其中一份还指向已迁移的术语表）；
- `docs/plans/active/` 滞留 5 月的休眠计划，"active" 失去含义；
- `docs/reference/` 13 件中 10 件为带日期的过期调查，与常青指南混居；
- agent 常驻上下文（CLAUDE.md）13.7KB 且含两节重复。

需要一部高于惯例、可裁决冲突的成文规则。

## 决策依据：四个不对称

1. **记忆不对称**：agent 会话内完美、跨会话归零；人类持久但有损。→ 文件携带 agent 的跨会话记忆（作战地图 + issue），人类版本保存"大意形状"（驾驶舱）。
2. **疲劳不对称**：agent 读万行不累；人类十分钟疲劳。→ agent 层冗长精确，人类层短小可视。
3. **判断不对称**：人类拥有品味、方向、风险与预算；agent 拥有执行宽度与机械一致性。→ 决策路由给人（决策队列），事实路由给 agent（登记簿）。
4. **信任不对称**：agent 的声明需要证据（会一本正经地错）；人类的决定需要留痕（会忘记拍过板）。→ "完成"挂证据，"拍板"写记录。

## 决策：宪法七条

全文常驻 `CLAUDE.md` 顶部（双全景 / 按需加载 / 人类层单向 / 真相时态 / 证据与验收 / 固定节奏自清洁 / 一切可推翻），并以分区宪章（路由表）规定每个文档分区的时态、读写方与死亡规则。

配套机制：issue 为工作单元（验收条件前置、证据贴评论、`Closes #N`、关单留结语、每轮收尾卫生清扫）；一轮一张作战地图；串行执棒；`doc-auditor` 作活法律的漂移审计器；solutions 经验按 frontmatter 过期条件流转、反复引用者晋升 skill。

## 考虑过的替代方案

- **按读者分两套文档（agent 版 / 人类版）**：同一事实两份必然漂移（AGENTS.md 27 行漂移为实证）。否决；改为"一份规范源 + 非规范人类投影"。
- **全部状态住 GitHub issue**：issue 不随 git 版本化、离线不可见、与代码历史不原子绑定。否决纯 issue 方案；采用"issue 管做什么与做到哪了，仓库管什么为真与为什么"。
- **不立宪，靠惯例与就事论事**：已被本轮盘点的漂移与堆积证伪。

## 后果

- `CLAUDE.md` 全面重写并设预算上限（≤9KB，进一字挤一字）；`AGENTS.md` 改为其 symlink，物理消灭双副本。
- 推翻先前「agent 开局读驾驶舱」协议：驾驶舱改为 agent 只写不读，开局现场恢复改读作战地图 + open issues。
- 分区宪章生效；既有指示与宪法冲突时，修订既有指示。
- 修宪须新增 ADR；本文件即首例与格式先例。
