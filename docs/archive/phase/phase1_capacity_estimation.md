# Phase 1 产出：设备容量与性能约束评估

> ⚠️ 本文档为设计阶段的容量评估与风险研判，所有性能结论和风险等级均为**基于规格的预估**，
> 需通过真机验证后才能作为硬约束依据。标注"无风险/低风险"的场景已在 v0.1~v0.2 部分验证，
> 但 HDR 链路、8K 性能、长时功耗等场景的验证见 `quality_gates.md` 和 `known_issues.md`。

## 目标平台硬件规格

| 参数 | Apple Vision Pro |
|---|---|
| 芯片 | M5（4 个性能核心和 6 个能效核心 128GB/s 内存带宽）+ R1 协处理器（12ms 光子到光子延迟、256GB/s 内存带宽） |
| 内存 | 16 GB 统一内存（系统+应用共享） |
| GPU | 10 核 Metal GPU |
| 视频解码器 | 硬件解码引擎（VideoToolbox），支持 H.264, HEVC, VP9, AV1 |
| 显示 | 双 Micro-OLED（单眼 3660x3200），90Hz、96Hz、100Hz、120Hz |
| 存储 | 256GB / 512GB / 1TB |
| 网络 | Wi-Fi 6 |

## 关键性能场景评估

### 场景 1：4K HDR 视频播放

| 指标 | 评估 |
|---|---|
| 典型码率 | 20~80 Mbps |
| 解码方式 | VideoToolbox 硬件解码，M5 芯片原生支持 |
| 内存占用 | 解码缓冲区约 200~500MB（含帧缓存池） |
| GPU 负载 | YUV→RGB 转换 + Metal 纹理上传 + RealityKit 场景渲染 |
| 风险等级 | 无风险，M5 对 4K HEVC 硬件解码轻松应对 |

### 场景 2：8K / 16K 超高码率视频

| 指标 | 评估 |
|---|---|
| 8K 典型码率 | 100~400 Mbps |
| 解码能力 | 8K 在可控码率下具备落地可行性；16K 仅作为实验性场景，不纳入 MVP 承诺 |
| 内存带宽 | R1 协处理器 256GB/s 带宽，帧传输无瓶颈 |
| 风险等级 | 中风险。除网络外，还需验证热管理、内存压力和长时播放稳定性 |

### 场景 3：远程 SMB/WebDAV 播放

| 指标 | 评估 |
|---|---|
| 网络带宽 | Wi-Fi 6 理论 1.2Gbps，实际家庭环境 200~500 Mbps |
| 4K 视频需求 | 20~80 Mbps，Wi-Fi 6 完全满足 |
| 8K 视频需求 | 100~400 Mbps，接近 Wi-Fi 实际吞吐上限，可能受用户网络环境影响 |
| 缓冲策略 | MPV 内置读取缓冲区，可配置预缓冲时长 |
| 风险等级 | 远程播放主要受 Wi-Fi 质量影响，同时受重连策略和缓冲参数设计影响 |

### 场景 4：3D 虚拟场景 + 视频同时渲染

| 指标 | 评估 |
|---|---|
| GPU 负载 | RealityKit 场景渲染 + 视频帧纹理更新（每秒 24~120 帧） |
| 帧率目标 | visionOS 合成器支持 90/96/100/120fps |
| 风险等级 | 低风险，M5 GPU 可充裕承载视频解码与 3D 场景并行渲染 |

## 存储容量评估

| 数据类型 | 预估大小 | 增长趋势 |
|---|---|---|
| 播放进度记录 | 每条约 200 字节 | 极低，5 天自动清理 |
| 用户设置 | < 10 KB | 基本不增长 |
| 连接配置 | 每条约 500 字节 | 极低 |
| 应用本体 | 约 50~100MB（含 MPV 库） | 随版本更新 |

> 结论：本地持久化数据量极小，无需数据库扩展方案。SwiftData 轻量模型完全满足需求。

## 单点故障与瓶颈审查

| 故障点 | 影响 | 缓解策略 |
|---|---|---|
| SMB/WebDAV 服务器宕机 | 无法浏览和播放远程文件 | 错误提示 + 后台重连机制（需求已定义） |
| Wi-Fi 信号不稳定 | 远程播放卡顿/中断 | MPV 预缓冲 + 断连重连逻辑 |
| MPV 解码失败 | 个别格式播放异常 | 错误提示，不崩溃主进程 |
| 长时间播放温升 | 降频、掉帧、续航下降 | 增加功耗预算 + 真机 60 分钟稳定性门禁 |
| 事件处理积压 | 播放状态错乱、进度不同步 | 独立事件循环 + 队列监控 + 高频事件合并 |

## 总结

Enchron 作为纯客户端应用，Vision Pro 的解码与图形能力足够强，主要风险不在“能不能播”，而在“能否长时间稳定且低功耗地播”。

1. **网络质量与重连策略**：远程 8K 播放受用户网络和客户端重连策略共同影响  
2. **libmpv 在 visionOS 上的兼容性**：编译适配是 Phase 4 首个垂直切片需要验证的内容  
3. **功耗与热管理**：需要真机长时播放门禁，避免只在短测下“看起来可用”
