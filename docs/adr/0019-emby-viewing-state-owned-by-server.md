# 0019 — Emby 来源媒体的观看状态由服务器拥有

- Status: 已采纳
- Date: 2026-08-12

## 背景

Enchron 接入 Emby 作为媒体服务器来源。Emby 服务器本身为每个用户维护观看进度、已看完状态、继续观看与下一集关系，并对该服务器的所有客户端保持一致。Enchron 同时已有本地的 Persistent Viewing State 机制，按 Media Identity 持久化可恢复位置，并在播放结束时经过本地判定策略（最短时长门槛、临近结尾清除等）决定写入内容。

若 Emby 来源媒体同时写入本地观看状态，会形成两份权威：本地判定策略与服务器判定规则互相加工，跨客户端显示不一致，并逐步催生同步时间戳、冲突解决、离线变更队列等 Enchron 播放器不需要承担的复杂度。

## 决策

Emby 来源媒体的观看进度、已看完状态与音轨字幕选择以服务器为唯一权威：

- 打开条目时从服务器读取状态；播放期间与停止时向服务器上报原始播放位置，本地判定策略不参与；上报失败静默丢弃，不重试、不排队、不补报。
- 本地媒体记录中的观看状态与音轨字幕选择两格对 Emby 来源禁止写入；画面格式与播放模式等 Emby 不理解的 Enchron 偏好仍本地持久化。
- 该归属由播放启动请求携带的 Viewing State Authority 在类型层面表达，写回路径对其穷尽分支，不依赖调用方自律。

## 接受的限制

- 服务器不可访问时，Enchron 不提供 Emby 媒体的离线观看状态。
- 服务器未提供的跨会话恢复能力（如按条目记忆音轨选择），Enchron 不以本地数据库补齐，回退到服务器默认值。
- 极端退出场景可能丢失最后数秒进度，由服务器会话超时清理兜底。
