# 0003 — 用例表（Use Case Ledger）：行为的规范地基

- Status: 已采纳
- Date: 2026-06-12

## 背景

App 「有哪些用户可观察行为」此前只存在于代码与人脑，多 agent 换手时无 grep 可达的事实清单；`docs/product_philosophy.md` 故意声明 not a feature list，留下了这个空。需求：① 未来自动化测试的基准 ② agent 的功能盘点 ③ 新旧功能可对比、可判冲突。同时项目处于管线技术验证前夜，重构需要一份「行为不变」的对照法律先于重构存在。

## 决策

建 `docs/use_cases.md` 单文档（不开文件夹），时态活法律，登记进 CLAUDE.md 分区宪章。核心设计：

- **蓝图模式**：记应然行为而非现状快照。代码与表冲突默认表为准；报警走 issue（标题带用例 ID，证据丰富度随问题大小升级：文字→截图→录屏），发现者本轮不动代码也不动表。
- **验证状态三值**：`已验证`/`未验证`/`未实现`。语义是证据等级而非代码存在与否——「代码写了但有严重 bug」无歧义地落在 `未验证`。初版填表全标 `未验证`，凭记忆即可；测试阶段照表清库存，逐条升级。
- **裁决次序**：对代码表为准；对 ARCHITECTURE.md 互不裁决、冲突上报人类；对 product_philosophy.md 哲学为上游。
- **粒度公理**：一条用例 ⟷ 一个可观察断言 ⟷（未来）一个 UI 测试；表格单行写不下即拆。
- **ID 体系**：`UC-<前缀>-<序号>`，永不复用；前缀封闭名单（LNCH/FILE/SET/PLAY/SCEN），跨 surface 归触发动作所在章。编号不进业务代码，只住「本表 + 测试名」两处。
- **退役即删行**：废弃条目从正文删除，表尾退役名单追加一行墓碑（ID+日期+一句话），原文走 git history。
- **成功指标占位**：表内独立章节声明空缺与填充责任，禁止 agent 自行发明指标。

## 考虑过的替代方案

- **照片模式（只记现状）**：代码永远不可能与表冲突，裁决权名存实亡，也无法承载「未实现」的需求视野。否决。
- **状态字段记实现状态（已实现/未实现/部分实现）**：人无法逐条对照代码核实，且「代码存在但不工作」无处安放。否决，改为证据语义。
- **四值含 `已废弃`**：废弃条目是「曾经为真」，属时间戳记录时态，留在活法律文档里违反真相时态宪法。否决，改为删行+墓碑名单。
- **按 surface 拆文件夹**：判冲突要求用例共置；功能基本冻结，语料有界，无界增长的容器用不上。否决（沿袭前轮共识）。
- **小节式条目格式**：自由空间纵容多断言塞一条；表格行 grep 一行得全字段，且「写不下」本身是粒度警报。采用表格行。
- **人类 HTML 投影**：md 表格可读性已过线，第一期不建；需要时收尾协议向 `docs/cockpit/` 生成，零风险可逆。

## 后果

- 管线重构获得验收基准：重构前后表内行为全部不变（或按计划变化）。
- `未验证` 条目数即测试阶段的工作清单，无需另写测试计划。
- 表与代码的一致性在测试接管前靠人工/agent 巡检，这是已知且接受的弱报警期。
- `product_philosophy.md`「PRD 诞生日退位归档」的前提可能不再成立（用例表+哲学双文档替代了传统 PRD），将来顺手修订。
