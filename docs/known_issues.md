# XrPlayer 已知问题（Known Issues）

更新时间：2026-03-04

## KI-001：visionOS 播放大体积 MKV 时出现卡顿/掉帧（偶发音画短暂不同步）

### 现象
- 文件可正常打开，音画可播放。
- 播放过程中会出现短暂停顿（掉帧感），随后画面追上音频。
- 在高码率 HEVC + MKV 场景下更明显。

### 影响范围
- 平台：Vision Pro（真机）。
- 典型文件特征：`MKV + HEVC(Main10) + FLAC`，并带内嵌字幕轨（特别是 ASS/PGS 类型）。

### 当前判断（根因）
- 这不是“不能播放”的功能性错误，而是性能瓶颈问题。
- 字幕轨会显著增加每帧合成成本：
  - ASS/PGS 字幕通常需要逐帧排版/栅格化/叠加。
  - 在高分辨率视频下，字幕叠加与视频渲染竞争 CPU/GPU 时间片，容易造成帧时间抖动。
- MKV 解封装 + HEVC 解码 + FLAC 音频解码 + 字幕合成叠加在同一播放链路中，会放大抖动概率。

### 为什么“一个字幕”也可能导致卡顿
- 字幕不是“只显示一行文字”这么简单；复杂字幕（ASS 特效、描边、阴影、动画）可能每帧都要重新计算和绘制。
- 这类开销在高分辨率、高码率视频上会被放大，所以会出现“看起来只是字幕，但实际拖慢整条渲染链路”的情况。

### 当前临时策略（不降画质/不降帧率）
- 默认不自动启用字幕轨（`sid=no`），由用户手动开启。
- 优先保证主视频链路稳定，再逐步恢复字幕能力。

### 后续修复计划
- P1：加入可观测指标（丢帧计数、渲染延迟、音画同步偏差）并落日志，定位具体瓶颈点。
- P1：对字幕轨做分级策略（文本字幕优先、复杂特效字幕降级渲染路径），避免阻塞主渲染。
- P2：评估双引擎路线（原生 AVFoundation 处理可原生格式，mpv 作为非原生格式兜底）以提升稳定性。

### 验收标准（针对 KI-001）
- 连续播放 10 分钟内无明显卡顿峰值（主观可感知停顿次数显著下降）。
- 音画同步偏差控制在可接受范围，且无崩溃。
