# Enchron 产品哲学

Purpose: 定义产品为什么存在、追求什么体验、拒绝什么取舍。
Status: Active product philosophy.
Owner/scope: 产品原则、体验优先级、战略取舍。
This file is not a feature list, API contract, router spec, or implementation plan.

## 1. 产品的核心是什么

Enchron 是一款面向 visionOS 的沉浸式视频播放器。它的目标不是“在头显上播放视频”，而是让用户身处一个属于自己的虚拟空间，自然地观看内容。

三种播放模式定义产品的完整形态。

### 窗口模式

SwiftUI 窗口内播放，接近 iPad 体验。它是用户最先接触的界面，也是验证基础播放体验的地基。窗口模式必须足够好，但它不是终点。

### 沉浸场景模式

用户进入 3D 虚拟场景，视频显示在场景中的虚拟屏幕上。虚拟屏幕的远近、高度、视角均可调节，每个场景独立记忆观影位置。帧数据通过 Metal 纹理桥接渲染到 RealityKit 材质上。

这是产品的终极形态，呈现高质量的美术场景，也是核心差异化。当前所有交互设计、接口定义和模块边界都必须为它预留空间。

### 全景模式

360 度、180 度、鱼眼全景视频投射到包裹用户的球体或半球体内壁。它进入沉浸空间但不加载虚拟场景，以节省渲染资源。

### 三种模式的关系

三种模式共享同一套语义播放模型和控件体系，差异是呈现路径差异。`PlayerUI` 根据媒体事实和空间状态决定默认播放模式，用户也可以在合法范围内手动覆盖。

任何只在窗口模式下正确、但会与沉浸场景冲突的实现，都不应被接受。

## 2. 设计原则

### 播放体验是产品本体

UI/UX 不是功能的附属。用户的第一印象来自视频打开的那一刻：是否秒开，是否黑屏，控件是否一眼看懂，拖动是否跟手。这些决定产品在用户心中的定位。

### 性能是感知，不是指标

不追求 benchmark 数字。追求的是用户不感到卡，功耗不过高。动效发木、时间轴拖动不跟手、模式切换掉帧，都是产品缺陷。

### HDR 可信度是底线

用户未必能说出 HDR10、HLG、Dolby Vision，但会直接感受到颜色对不对、高光是否被压坏。HDR 标签一旦显示，就必须可信。

### 系统原生优先

能用系统容器就不造容器，能用系统材质就不自定义材质，能用系统动效就不写自定义动画。只有在系统方案无法满足核心体验时才自定义，而且每次自定义都要回答：它是否真的让核心体验更好了？

### 媒体引擎策略

Enchron 的长期媒体策略是 **Apple-native first, mpv-safe fallback**。

mpv 是开放格式和复杂媒体的兼容性基线。对于 MKV、WebM、AVI、TS/M2TS、FLV、复杂字幕、复杂音轨、脏输入、远程 I/O 不稳定或元数据不足的媒体，mpv 仍然是默认可信路线。

Apple AV / AVKit 是 Apple 原生媒体体验的上限。对于 Apple-native 容器、HLS、Photos asset、Spatial Video、MV-HEVC、Apple immersive media、系统 HDR/EDR 行为和未来 visionOS 媒体能力，Apple route 是优先方向。

三种播放模式仍然共享一套语义播放模型。窗口、沉浸场景和全景模式的差异是呈现路径差异，不是播放引擎语义差异。

## 3. 具体设计取向

### 组件与动画

- 普通场景优先使用 Apple 自带容器、过渡、材质、排版系统。
- 复杂交互只在关键体验区自定义，例如统一时间轴的精确时间标签、逐帧步进、特殊 scrubbing 行为。
- 动画服务状态变化和空间理解，不做装饰。
- 若动画与清晰度或性能冲突，优先清晰度与性能。

### 播放控件

三种模式共享同一套控件体系，区别仅在于宿主环境。设计控件时必须同时考虑窗口和沉浸场景下的呈现：

- 不允许出现功能可触发但视觉上几乎消失的控件。
- 不允许重要操作没有明确 focus / hover / active 反馈。
- 不允许用户需要反复试错才能命中关键控件。
- 控件层级应清楚：主动作、次动作、精确操作入口必须能一眼分辨。

### 统一时间轴

统一时间轴是本产品的核心体验资产。它将精确控制和基础进度操作合二为一：

- 拖动时内联显示精确时间标签，含帧号，无需切换模式。
- 逐帧步进按钮始终可见于控件区，一步到达精确帧。
- 进度条可直接拖动 seek，松手即跳转。

如果一个改动让时间轴更难拖动、精确时间标签不准确或逐帧步进不灵敏，应视为退化。

### HDR

- HDR 类型识别必须稳定。
- 标签显示必须可信，不可误报。
- HDR / SDR 切换必须符合预期。
- 映射错误、色彩偏差、高光被压坏，属于高优先级问题。

### 沉浸场景的设计约束

沉浸场景对当前设计产生持续约束：

- `PlayerUI` 的控件布局必须考虑未来在 3D 空间中浮层呈现的可能。
- `PlaybackCore` 的帧输出接口必须支持 MTKView 直接渲染和 Metal 纹理桥接两类能力表达。
- 播放模式决策逻辑应由 `PlayerUI` 持有，通过查询 `SpatialScene` 状态来决定呈现路径。

## 4. 非目标 / 反模式

以下方向不是当前产品要追求的：

- 为了看起来高级而堆砌复杂动画。
- 为了参数自由度而把产品做成发烧友调参面板。
- 为了局部视觉创意而破坏系统一致性。
- 为了追求功能数量而牺牲播放体验主线。
- 为了快速修 bug 而引入体验层面的长期补丁。
- 为了窗口模式的临时修复而引入与沉浸场景不兼容的架构决策。
