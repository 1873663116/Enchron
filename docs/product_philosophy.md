# Enchron 产品哲学

Purpose: 定义产品为什么存在、追求什么体验、拒绝什么取舍。
Status: Active product philosophy.
Owner/scope: 产品原则、体验优先级、战略取舍。
This file is not a feature list, API contract, router spec, or implementation plan.

## 1. 产品的核心是什么

Enchron 是一款面向 visionOS 的沉浸式视频播放器。它的目标不是“在头显上播放视频”，而是让用户身处一个属于自己的虚拟空间，自然地观看内容。

三种播放模式定义产品的完整形态。

### 窗口模式

SwiftUI 窗口内播放，它是用户最先接触的界面，也是验证基础播放体验的地基。窗口模式需要足够好，但它不是终点。

### 沉浸场景模式

用户进入 3D 虚拟场景，视频显示在场景中的虚拟屏幕上。虚拟屏幕的远近、高度、视角均可调节，每个场景独立记忆观影位置。播放画面由外部 `PlaybackCore` 提供，Enchron 负责把它组装进 RealityKit 呈现表面。

这是产品的终极形态，呈现高质量的美术场景，也是核心差异化。当前交互设计、接口定义和模块边界都要为它预留空间。

### 全景模式

360 度、180 度、鱼眼全景视频投射到包裹用户的球体或半球体内壁。它进入沉浸空间但不加载虚拟场景，以节省渲染资源。

### 三种模式的关系

三种模式共享同一套语义播放模型和控件体系，差异是呈现路径差异。`PlayerUI` 根据媒体事实和空间状态决定默认播放模式，用户也可以在合法范围内手动覆盖。

只在窗口模式下正确、但会与沉浸场景冲突的实现，会把未来核心体验锁死。

### 媒体引擎策略

Enchron 不拥有媒体引擎。独立的 `PlaybackCore` 是唯一播放核心，负责媒体来源接入、轨道与播放状态、sample-buffer 生产、同步和渲染输入协调；Enchron 只持有产品级播放请求、界面状态与呈现生命周期。

`PlaybackCore` 内部的 Apple Compressed 与 FFmpeg Compressed 是同一核心中的两条显式路线，不是 Enchron 的双引擎路由。Enchron 不探测路线、不实现失败回退，也不把底层选项直接暴露成产品模型。

远程来源、字幕、HDR 与新媒体能力先在 `PlaybackCore` 中形成稳定契约，再由 Enchron 的薄适配层接入。任何新的播放后端都需要独立架构决策，不能因历史代码存在而成为产品方向。

## 2. 具体设计取向

### 组件与动画

- 普通场景优先使用 Apple 自带容器、过渡、材质、排版系统。
- 复杂交互只在关键体验区自定义，例如统一时间轴的精确时间标签、逐帧步进、特殊 scrubbing 行为。
- 动画服务状态变化和空间理解，不做装饰。
- 若动画与清晰度或性能冲突，优先清晰度与性能。

### 播放控件

三种模式共享同一套控件体系，区别仅在于宿主环境。设计控件时同时考虑窗口和沉浸场景下的呈现：

- 功能可触发但视觉上几乎消失，是可用性风险。
- 重要操作缺少明确 focus / hover / active 反馈，是空间交互风险。
- 用户需要反复试错才能命中关键控件，是命中区域或视觉层级风险。
- 控件层级应清楚：主动作、次动作、精确操作入口必须能一眼分辨。

### 统一时间轴

统一时间轴是本产品的核心体验资产。它将精确控制和基础进度操作合二为一：

- 拖动时内联显示精确时间标签，含帧号，无需切换模式。
- 逐帧步进按钮始终可见于控件区，一步到达精确帧。
- 进度条可直接拖动 seek，松手即跳转。

如果一个改动让时间轴更难拖动、精确时间标签不准确或逐帧步进不灵敏，应视为退化。

### HDR

- HDR 类型识别需要稳定。
- 标签显示需要可信，不可误报。
- HDR / SDR 切换需要符合预期。
- 映射错误、色彩偏差、高光被压坏，属于高优先级问题。

### 沉浸场景的设计约束

沉浸场景对当前设计产生持续约束：

- `PlayerUI` 的控件布局要考虑未来在 3D 空间中浮层呈现的可能。
- Enchron 的播放适配层只消费 `PlaybackCore` 提供的呈现能力，不复制 renderer、同步器或帧队列。
- 播放模式决策逻辑应由 `PlayerUI` 持有，通过查询 `SpatialScene` 状态来决定呈现路径。

## 4. 产品边界

以下取向会稀释产品主线：

- 为了看起来高级而堆砌复杂动画。
- 为了参数自由度而把产品做成发烧友调参面板。
- 为了局部视觉创意而破坏系统一致性。
- 为了追求功能数量而牺牲播放体验主线。
- 为了快速修 bug 而引入体验层面的长期补丁。
- 为了窗口模式的临时修复而引入与沉浸场景不兼容的架构决策。
