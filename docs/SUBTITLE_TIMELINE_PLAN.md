# 字幕时间线计划

## 一、现在的事实

字幕有两条读取路径，共用同一套「按时间查询」的接口。

外挂字幕文件。选中时把整个文件读完，得到完整的「时间 → 文字」表。查询与播放位置无关。

内嵌字幕。文字轨与位图轨（PGS）都向共享解复用源订阅一条流，只收到订阅之后的那一段包。文字轨把收到的包解成语句，逐句加入清单；位图轨把收到的包解成图片，维持一个滑动窗口。

```
内嵌字幕
  订阅 ──> 只收到「订阅点之后」的包
        ──> 文字：清单只覆盖这一段
        ──> 位图：窗口只覆盖这一段
  跳转 ──> 订阅点不动，清单与窗口都不动
```

实测（远程 ISO，跳到 620 秒后连续 25 秒）：

```
subtitle.frame.idle at=625 ingested=120 covered=70.404..119.364
subtitle.frame.idle at=645 ingested=120 covered=70.404..119.364
```

字幕数据停在 119 秒，播放时钟在 645 秒。此时查询返回空，界面不显示字幕或显示旧字幕。

会话每 0.1 秒用播放时钟查询一次「此刻显示什么」。查询本身正确，错的是被查询的数据没有跟上位置。

## 二、目标

字幕与画面、声音共用同一个位置。跳转到某处，三者从同一处取数据。

```
                共享源（读取位置 + 保留的历史）
                          │
        ┌─────────────────┼─────────────────┐
        │                 │                 │
     视频车道          音频车道          字幕车道
   按时间戳交付      按时间戳交付      按时间点回答「显示什么」
        │                 │                 │
        └──────────── 同一个播放时钟 ────────┘
```

字幕车道与另两条车道的差别只在输出形态：它不提前交出样本，而是按需求值。

## 三、结构改动

挂载点等于请求时间。选中字幕或跳转之后，字幕车道按目标时间向共享源要数据，源从保留的历史里给出不早于目标的包。它不再「从订阅那一刻往后收」。

跟随跳转。跳转时字幕车道先摘下，源移动位置，再按新目标挂上。摘下的动作不得清空别的车道正在使用的队列。

同一条流允许换主人。一条流现在只能有一个订阅者，换主人的一瞬间新的建不起来，旧的释放又会把新的废掉。订阅改成引用计数，或改成按纪元登记。

查询接口不变。会话仍每 0.1 秒问一次，界面层不动。

文字轨与位图轨的差别只在解码输出，位置与生命周期共用同一套。

## 四、验收

一，跳到任意位置，三秒内显示出该位置对应的字幕。

二，片子开头第一句字幕，在它该出现的时间前后 0.2 秒内出现。

三，连续播放十分钟，字幕持续跟随画面。

四，跳转后一秒内，字幕数据窗口的下界不早于目标时间减一秒。

每条都以运行时日志为据：`subtitle.frame.produced` 的 `at` 必须落在 `range` 内，且与 `range.start` 相差不超过 0.2 秒；`subtitle.frame.idle` 的 `covered` 下界必须跟随播放位置。

## 五、实施顺序

一，订阅改成可以换主人，并加一条测试：旧订阅释放后，新订阅仍能收到包。

二，字幕车道按请求时间挂载，复用音频车道的「从历史取包」实现。加一条测试：跳过之后，窗口覆盖目标时间。

三，会话在跳转完成时重挂字幕车道。加一条测试：跳转后三秒内产生覆盖目标的帧。

四，用真实片子跑一次端到端，记录跳转前后的 `covered` 与 `at`/`range`。

## 六、未决

外挂字幕文件当前走整份读取，跳转后仍然可用；接入车道之后保持这条路径不变。

3D 蓝光的字幕有左右眼两份位图，车道模型不区分，按普通位图处理。
