mpv 在 visionOS 上的视频管线 — 输出产物视角

关键区分：内部中间产物（只在 mpv/libplacebo 管线内部流转，外部拿不到，也接不上 visionOS 抽象） 与 真实输出产物（mpv 的"出口"，可以被 CAMetalLayer / MTLTexture / RealityKit 消费）。 VideoToolbox 是 vd_lavc 内部的硬解 hwaccel，不是独立下游阶段；它产出的 CVPixelBuffer 是 hwdec 中间产物， 在原生路径下被 libplacebo 零拷贝吃进去，不会直达 RealityKit。真正到 RealityKit 的是 libplacebo 之后的 rgba16Float drawable。

两个真实"出口"，各拿到什么

  • 原生 GPU 路径：出口是 CAMetalLayer（App 经 wid 注入）及其 drawable 的 MTLTexture rgba16Float。窗口模式直接上屏；沉浸模式由 PanoramaLayerBridge 逐帧 blit/compute 拷进 LowLevelTexture。
  • 软件路径（模拟器）：出口是 MPV_RENDER_API_TYPE_SW 渲出的 CVPixelBuffer (BGRA)，交给 FrameOutput。

原图的主要修正点

  • VideoToolbox 并入 vd_lavc（内嵌 hwaccel），不是独立下游阶段。
  • CVPixelBuffer(NV12/p010) 标注为 hwdec 内部中间产物，经 hwdec_vt_pl 零拷贝导入 libplacebo，不直达 RealityKit。
  • CAMetalLayer 由 App 经 wid 提供，并补充 vkCreateMetalSurfaceEXT 这一 MoltenVK 细节。
  • RealityKit 分叉是逐帧 GPU 拷贝（读 lastVendedDrawable），非零拷贝共享。
  • 补回软件/模拟器输出路径（CVPixelBuffer BGRA）。
