# 串流移植 · 剩余验证清单

> 基线：`.scratch/2026-10-27-gate-sim/summary.md`（2026-10-27 上午）。主机 + 模拟器的注入回路已打通：模拟器 App 的调试通道把输入与反馈注入生产路径，真主机 Apollo 收到并落到 ViGEm 虚拟手柄与桌面输入，主机记录器写 JSONL。本清单只列「尚未核实且能够核实」的项。

## 0. 口径

| 项 | 定义 |
| --- | --- |
| 已核实 | 有探针行、主机记录或截图为证，证据已归档 |
| 未核实 | 没有证据，或只有单测/代码阅读支撑 |
| A 类 | 现有工装直接可验证：模拟器 + 调试通道 + 真主机 + loopback 代理 + 主机记录器 |
| B 类 | 需要少量工装：新增 DEBUG 测试动词或探针、主机侧配置/脚本 |
| C 类 | 需要 UI 或手势驱动：模拟器 XCUITest 或 Device Hub 合成手势 |
| D 类 | 不能验证：真实硬件手感、面板、声场、真实广域网与佩戴者行为 |

通过判据：判据满足 + 证据归档到 `.scratch/<日期>-<主题>/evidence/`。失败判据：判据不满足，登记缺陷。受阻判据：工装缺失，转 B/C 类并在结果表标记 `blocked`。

模拟 lane 的安装核对沿用真机流程：最终验证前用 `Scripts/build/install_to_simulator.sh` 覆盖安装，启动后核对运行进程的容器与安装返回的容器一致。

批准范围建议为第 1 至第 3 批：包含仅 DEBUG 的测试通道与探针改动、主机 Apollo 的一次 debug 级别重启、主机侧脚本与模拟器 UI 驱动；产品运行路径不改变。第 4 批为收尾核对。
