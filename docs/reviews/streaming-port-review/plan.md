# 串流补齐移植 · 执行方案 v1

> 本方案由 48 个审查单元的裁决生成：移植 32、移植（替代实现）1、不移植 15。
> 本方案中「验收」一节是本次被 review 的主体；端到端测试框架不在本次改造范围内，按约定只做三件事：扫描并更新 feature map 文档、保证测试 CLI 动词可达、保证单元测试跑通。

## 0. 依据与口径

| 项 | 决定 |
|---|---|
| 对齐基准 | moonlight-ios 上游 master（克隆提交 `02dc978`）；visionOS 社区分支只作VisionOS平台实现参考 |
| 实现形态 | 混合：协议与输入编码、回程回调留在 Objective-C 桥接层；采集、界面与交互留在 Swift |

### 1.3 裁决组合产生的三条收敛决定

1. **U18 的落地范围收缩。** 原单元包含五项设置，其中「多手柄」「屏幕控件」对应的能力已被 U9、U10 判为不做。为避免出现拨了没反应的开关，U18 落地为三项：触摸模式、统计浮层开关、多声道音频开关。
2. **U19 按上游常量对齐。** 该项原本无差距（我们用 32767 与四舍五入，上游用 32766 与截断）。裁决为移植，因此按上游常量改写，属于不可感知的改动，可一行回退。
3. **退出路径为零。** U9、U11、P2 全部不移植，意味着本次改造后**没有任何新增的退出串流方式**：手柄上没有组合键，界面上没有按钮，仍然只能关窗口。这是裁决的必然结果，不是遗漏。

### 4.3 新增探针与通道

探针统一走现有会话探针设施，按「一行一条事实」记录，保留为证据级：

| 探针 | 触发 |
|---|---|
| `gamepad arrival type=… caps=… buttons=…` | 每次握手 |
| `gamepad arrival sent t=… afterConnection=…` | 握手时 |
| `gamepad rumble recv low=… high=…` / `gamepad rumble applied=…` | 收到回传与下发引擎 |
| `gamepad motion request=…hz samples=…` | 每秒汇总 |
| `gamepad battery level=… state=…` | 上报时 |
| `gamepad led r=… g=… b=…` | 收到颜色 |
| `gamepad touchpad x=… y=… down=…` | 坐标事件 |
| `pointer lock window=…` | 锁定请求 |
| `connection quality=…` | 质量回调 |
| `audio channels=…` | 协商完成 |
| `transport remote=… packet=…` | 建链 |
| `display criteria frameRate=… hdr=…` | 显示模式申请 |
| `reconnect reason=…` | 重连 |

新增测试通道动词只在确有必要时添加（例如注入震动、注入触摸板）；每个动词需在 `Scripts/`、`Regression/operations/` 或可达性清单中登记，否则会被孤立动词检查判失败。

### 4.4 真机 gate 固定流程

1. 全部测试跑完，再重建当前工作树。
2. 用 `Scripts/build/install_to_simulator.sh` 或有签名通道覆盖安装。
3. 启动该产物。
4. 核对运行进程的安装容器与本次安装返回的容器一致。

四项缺一即判失败。

## 6. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 握手声明能力后主机立刻索要体感或震动，而该部分尚未落地 | 崩溃或静默丢包 | 阶段 1 一次性落地三项回传；未实现分支先判空 |

| S9 依赖外部服务与网络条件 | 实现可能超期 | 独立成小阶段；不阻塞其他项，失败则降级为手动地址 |
| U19 改动量化常量 | 手柄满量程值变化 | 有单测钉住；可一行回退 |
