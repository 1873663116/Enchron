# 车道挂载与切换方案

本文是音频车道与字幕车道在切换、跳转之后出现静音、字幕缺失、时间错位的唯一验收依据。状态变化时更新本文。

## 一、范围

本文涉及三条车道：视频、音频、字幕。三条车道共用同一个解复用源。视频车道建立读取器时传入起始位置；音频车道与字幕车道不传。

## 二、现象

一，切换音轨后无声音，画面继续播放。跳转一次后声音恢复。

```
21:53:57.718  audio.select.request index=1
21:53:57.775  audio.attach.open reason=selection index=1 codec=truehd
              queuedBefore=43098 queuedAfter=74324 headBefore=1300.815 sourceStart=0.000
```

切换发生在播放位置约 1315 秒处。接管瞬间，队列最老的包位于 1300.815 秒。落后 14.2 秒。

二，切换音轨或跳转之后，字幕缺失或时间错位。字幕车道的接管方式与音频车道相同。

三，切换音轨在部分片段无缝，在部分片段中断。中断时长取决于接管瞬间队列内的包数量。

## 三、原因

解复用源为每条流维护队列。读取线程对所有音频流与字幕流持续入队，不区分是否存在消费者。队列只有入队与出队，不含播放位置。

车道接管一条流时，取得的是队列中最老的包，不是接管瞬间的播放位置。

```
读取线程 ──入队──▶ 队列[1300.8 … 1315.0] ──出队──▶ 车道
                              ▲
                              └── 出队起点是队列头，不是播放位置
```

视频车道不受影响，原因是建立读取器时传入起始位置，源按该位置裁剪。音频车道与字幕车道缺少该约定。

跳转可以恢复声音，原因是跳转重建队列，队列头因此回到播放位置。

## 四、目标一：挂载位置等于播放位置

行为。选中音轨、选中字幕轨、跳转之后，音频车道与字幕车道从接管瞬间的播放位置开始取包。

观测。接管日志在同一行记录三个量：`position` 是接管瞬间的播放位置，`firstDeliveredPTS` 是接管后该车道收到的第一个包的呈现时间，`firstDeliveryMillis` 是从接管到收到第一个包的墙钟耗时。

要求一，`firstDeliveredPTS ≥ position`。该条件无容差。低于 `position` 即表示车道从过去开始，判为失败。

要求二，`firstDeliveryMillis ≤ 400`（见目标二）。该条件按墙钟计，不按呈现时间计。

队列头 `headBefore` 只用于诊断，不作为判据。原因：字幕包稀疏，无台词区间可长达数十秒，队列头的呈现时间与播放位置的距离由内容决定，不是缺陷。音频包间隔约 0.03 秒，字幕包间隔由内容决定，两者不能共用同一个容差。

失败。`position − headBefore` 大于一秒，且此后十秒内不减小。

结构。三条车道共用同一个挂载入口。入口接收播放位置参数。源按该位置丢弃队列中较早的包。

## 五、目标二：接不上就进入加载态

行为。选中音轨、选中字幕轨、跳转之后，会话为该车道设定四百毫秒期限。车道在期限内交付新样本，播放继续。车道超过期限未交付，会话进入加载态：暂停呈现，显示加载界面，待车道交付后起播。播放态期间不得出现无声画面或无字幕画面。

观测。日志记录三个时刻：请求时刻、车道首次交付时刻、加载态进入与退出时刻。

失败。车道超过期限未交付，且会话保持播放态。

结构。期限按车道在会话层判定。加载态复用既有就绪状态。音轨与字幕轨使用同一判定。

约束来源。无缝切换不得以视频静音为代价。接管未在期限内完成时，暂停并显示加载态优于继续呈现无声画面。

## 六、目标三：切换音轨为一次原子交换

行为。用户确认新音轨后，界面立即标记新音轨为选中状态，菜单不阻塞。声音在两百毫秒内切换至新音轨。切换在同一采样边界完成：旧音轨先静音，新音轨后出声，两者不重叠。

观测。日志记录四个时刻：请求时刻、新车道就绪时刻、旧车道静音时刻、新车道出声时刻。

失败。切换后两条音轨同时出声。或旧音轨停止与新音轨出声之间超过两百毫秒。或界面标记的音轨与实际出声的音轨不一致。

结构。切换是同一采样边界上的原子交换：静音旧车道与启用新车道在同一步完成。不执行交叉淡入淡出。

约束来源。两条音轨内容不同。交叉淡入淡出会使两种语言或正片与评论同时可闻。

## 七、不变量

以下五项在每次改动后重跑，全部成立才算通过。

一，连续播放十分钟，音画同步，字幕跟随，无无声段。

二，跳转后三秒内三条车道均从新位置继续。

三，切换音轨三次。每次在四百毫秒内出声，或进入加载态并在此后起播。不出现无声画面。不出现两条音轨同时出声。

四，切换字幕三次。每次在四百毫秒内出现字幕，或进入加载态并在此后起播。不出现旧字幕残留。

五，上述四项在慢速源与本地源上各执行一次。

## 八、执行顺序

一，目标一。目标一解释现象一与现象二。改动集中在解复用源与挂载入口。

二，目标二。目标二保证接管失败时的用户可见状态。

三，目标三。目标三依赖目标一的队列裁剪与目标二的状态机。

## 九、未决

一，读取线程对所有音频流入队且不裁剪。队列曾积累至 74324 个包，约四十分钟音频。该积累的成因未查明。

二，字幕车道的跳转重建路径与音频车道不同。两条路径需收敛至同一挂载约定。

三，四百毫秒期限的取值来源为人耳对音画不同步的容忍度，未做测量。

## 十、验证入口
