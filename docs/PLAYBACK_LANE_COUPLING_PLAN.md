# 车道挂载与切换方案

本文是音频车道与字幕车道在切换、跳转之后出现静音、字幕缺失、时间错位的唯一验收依据。状态变化时更新本文。

## 一、范围

本文涉及三条车道：视频、音频、字幕。三条车道共用同一个解复用源。视频车道建立读取器时传入起始位置；音频车道与字幕车道不传。

## 二、现象

一，切换音轨后无声音，画面继续播放。跳转一次后声音恢复。

```
21:53:57.718  audio.select.request index=1
21:53:57.775  audio.attach.open reason=selection index=1 codec=truehd
              queuedBefore=43098 queuedAfter=74324 headBefore=1300.815 sourceStart=0.000
```

切换发生在播放位置约 1315 秒处。接管瞬间，队列最老的包位于 1300.815 秒。落后 14.2 秒。

二，切换音轨或跳转之后，字幕缺失或时间错位。字幕车道的接管方式与音频车道相同。

三，切换音轨在部分片段无缝，在部分片段中断。中断时长取决于接管瞬间队列内的包数量。

## 三、原因

解复用源为每条流维护队列。读取线程对所有音频流与字幕流持续入队，不区分是否存在消费者。队列只有入队与出队，不含播放位置。

车道接管一条流时，取得的是队列中最老的包，不是接管瞬间的播放位置。

```
读取线程 ──入队──▶ 队列[1300.8 … 1315.0] ──出队──▶ 车道
                              ▲
                              └── 出队起点是队列头，不是播放位置
```

视频车道不受影响，原因是建立读取器时传入起始位置，源按该位置裁剪。音频车道与字幕车道缺少该约定。

跳转可以恢复声音，原因是跳转重建队列，队列头因此回到播放位置。

## 四、定义

以下符号在全文使用，不含经验常数。

`P` 播放位置。会话当前呈现的呈现时间。

`A(L)` 车道的挂载位置。车道接管流时由会话传入的呈现时间。

`D(L)` 车道的交付位置。该车道最近一次交付的包的呈现时间。从未交付时无定义。

`ε(L)` 呈现单位间隔。该流一个呈现单位的时长：视频为帧间隔，音频为音频帧间隔，字幕为显示集合间隔。由流本身决定，不由本文指定。

`selected(L)` 车道已被用户选中。

`playing` 会话状态。呈现继续推进的状态。

## 五、目标一：交付位置不落后于播放位置

性质。对任一车道 `L`，接管之后交付的每个包满足 `PTS ≥ A(L)`。且当 `selected(L)` 且状态为 `playing` 时，`D(L) ≥ P − ε(L)`。

观测。接管日志记录 `position`（即 `A(L)`）与 `firstDeliveredPTS`。交付日志记录每次交付的 `PTS`。

失败。任一次交付的 `PTS < A(L)`。或状态为 `playing`、`selected(L)` 成立，而 `D(L) < P − ε(L)`。

结构。挂载入口接收 `A(L)`。源在交出流之前丢弃 `PTS < A(L)` 的包。该裁剪由源执行，不由各车道各自执行。

说明。`ε(L)` 是该流自身的量，因此判据对音频、字幕、视频使用同一个形式，不需要为不同车道设不同容差。

## 六、目标二：就绪门覆盖全部已选车道

性质。状态为 `playing` 时，对每个满足 `selected(L)` 的车道，`D(L) ≥ P − ε(L)` 成立。该条件不成立时，状态为加载态。

观测。日志记录每次状态迁移：进入 `playing`、进入加载态、退出加载态，以及迁移时每个已选车道的 `D(L)` 与 `P`。

失败。状态为 `playing` 期间，存在已选车道使 `D(L) < P − ε(L)`。

结构。就绪门在会话层，对全部已选车道求值。不在车道内部各自判定。

说明。加载态时长、接管到首次交付的耗时是诊断量，记录但不作为判据。判据只有状态的合取式，不引入时间阈值。

## 七、目标三：音轨切换是同一采样边界上的交换

性质。切换期间任一时刻，恰好一条已选音轨车道满足 `D(L) ≥ P − ε(L)`。交换前后均成立。界面标记的音轨等于满足该条件的车道。

观测。日志记录请求时刻、交换时刻、交换前后两侧车道的 `D(L)`。

失败。存在时刻使零条或两条已选音轨车道满足该条件。或界面标记的音轨与满足该条件的车道不一致。

结构。交换在会话层执行：静音旧车道与启用新车道在同一步完成。不执行交叉淡入淡出。两条音轨内容不同，重叠会使两种内容同时可闻。

## 八、不变量

以下四项在每次改动后重跑，全部成立才算通过。

一，连续播放十分钟：任一时刻状态为 `playing` 时，全部已选车道满足 `D(L) ≥ P − ε(L)`。

二，跳转后：三条车道的 `A(L)` 均等于跳转目标，且此后满足第一条。

三，切换音轨三次：每次满足目标三的性质，且不出现零条或两条车道满足条件。

四，切换字幕三次：每次满足目标二，且不出现旧字幕残留。

## 九、执行顺序

一，目标一。目标一解释现象一与现象二。改动集中在解复用源与挂载入口。

二，目标二。目标二保证接管未完成时的用户可见状态，并使第一条对全部车道生效。

三，目标三。目标三依赖目标一的裁剪与目标二的就绪门。

## 十、未决

一，读取线程对所有音频流入队且不裁剪。队列曾积累至 74324 个包，约四十分钟音频。该积累的成因未查明。

二，字幕车道的跳转重建路径与音频车道不同。两条路径需收敛至同一挂载约定。

三，加载态的进入与退出目前由就绪门决定，不含时间阈值。是否需要时间阈值以处理读取线程卡死，未定。读取线程卡死属于源的问题，由看门狗处理。
