# 串流主机

Moonlight 标签页维护一个主机列表：添加主机、与主机配对、读取主机提供的应用清单。侧栏选中哪一台主机，右侧内容列就显示那一台的细节与应用网格，两者必须始终一致。

标签页由设置页 General 分区的 Moonlight 开关控制，默认关闭。关闭时标签页与侧栏分区都不出现。

## Sub-features

- 空状态下提供「添加主机」入口；已有主机时入口在侧栏的加号上。
- 添加表单支持手填地址，也支持从发现结果里挑一个地址添加。
- 提交表单后主机出现在侧栏，配对状态可读。
- 与未配对主机配对：App 给出 PIN，主机端确认后状态转为已配对。
- 选中侧栏任意一行，内容列切换到该主机的名称、地址、配对状态与应用网格。
- 应用网格读取主机提供的应用清单；清单读取失败时给出可见的失败说明，并仍然渲染首选条目的缺失位。
- 应用卡片显示主机为每个应用提供的图标。取不到图标时回落到占位图形。
- 主机名右侧的操作按钮弹出该主机的动作菜单，内容随配对与在线状态变化。
- 侧栏行左滑露出移除，二次确认后该行消失。
- 应用卡片长按给出「移除主机应用卡片」，确认后该卡片消失，主机上的应用不受影响。
- 一台主机可以保存多个地址：本地地址、主地址、备用地址与外网地址。可达性检查按「本地 → 主地址 → 备用 → 外网」顺序探测，把应答的那个提升为主地址；同一台主机换地址重新添加时并入已有记录，而不是产生第二行。
- 发现阶段读取 Bonjour 文本记录里的 MAC 并随主机保存。主机离线时详情里出现「唤醒主机」，魔术包发往全部候选地址与广播地址，端口覆盖 9、47009 与 47998–48010。
- 应用清单落盘缓存（容器 `Caches/enchron-app-lists/host-<id>.json`），进详情先显示上次清单；刷新失败一次会重试，仍然失败时保留缓存。
- 封面取磁盘已有文件、不再请求；没有缓存时下载并发上限为 4，失败重试一次。
- 主机被占用时提供两条出路：「回到运行中的应用」与「结束占用并启动」。后者先弹确认并写明将被结束的应用名。
- 发现流每 5 秒重起一次，在线状态每 5 秒轮询一轮；主机记录持久化可达性、当前游戏与编解码声明，重启 App 后行内容沿用上次状态。

## How to get to it (user POV)

主窗口底部的导航栏切到 Moonlight 标签页。侧栏顶部是主机列表，右上角是加号。空状态下内容列本身就是添加入口。

点加号打开添加表单，填地址提交。主机出现后点这一行，内容列换成详情；未配对时详情里出现配对按钮，点击后弹出 PIN。

主机详情里不再有移除按钮，也没有退出主机应用的按钮：离开串流已经向主机发出 cancel。

## Driving it with computer use

Preconditions: 同[串流呈现](streaming-presentation.md)。测试通道已建立，`Documents/test-commands/` 与 `Documents/test-responses/` 为空。

导航与配对确认走真实指针动作。主机侧的 PIN 确认在 Sunshine 的 Web UI 上完成，属于 `host-sunshine` 证据：

用 computer use 在模拟器窗口的对应位置点一下，坐标取自 `simctl io <UDID> screenshot` 的原图尺寸与点击位置。

配对状态与主机行内容读产品自己发布的 accessibilityValue：

```sh
./.scratch/stream-cmd.sh streamSnapshot '{}'
```

主机的真实配对记录落在容器的 `Library/Application Support/Enchron/streaming-hosts.json`，客户端证书在同目录的 `moonlight-identity/`。这两份随容器存活，覆盖安装不丢。被移除的应用卡片以 `hiddenAppIDs` 记在同一份文件里。

应用图标落在容器的 `Library/Caches/enchron-app-artwork/`，按主机与应用各一份。

## 证明的终态

一次会话建立前，主机必须同时满足：侧栏存在该行、内容列的详情指向同一台主机、`hasPairingRecord` 为真、应用清单非空。四条缺一条都不能进入启动单元。

## Gotchas

- **侧栏与内容列的一致性只由产品保证。** 用命令通道直接改状态会绕过选择逻辑，因此这条一致性的唯一有效驱动是真实点击侧栏的每一行。
- **配对记录在容器里，不在 App 包里。** 覆盖安装保留配对；删 App 或抹掉容器才会丢。
- **模拟后端会混入应用清单。** 见[串流呈现](streaming-presentation.md)的 Gotchas。
- **图标请求走二进制响应，不走 XML 状态解析。** PNG 没有 status 属性，用通用的 XML 响应类型会把主机已经发来的数据判为失败。
- **移除应用卡片只写本地记录。** 主机上的应用列表不变，重新添加主机才会恢复该卡片。
