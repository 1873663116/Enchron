# 串流设置

设置页的 Moonlight 分区决定下一次串流向主机请求什么。这些取值只影响下一次请求，不改变进行中的会话。

## Sub-features

- 分辨率按像素总量从小到大排列：1280×720、1920×1080、2560×1440、3360×1440、5120×1440、3840×2160，末项是自定义。
- 自定义分辨率的宽高由步进器调整，宽度范围 320 到 7680，高度范围 240 到 4320。
- 帧率取值为 30、60、90、120 fps。
- 码率滑杆是 19 档非等距取值，最高 200 Mbps，低段更密。
- 选择预设分辨率或帧率后，码率跳到该组合的建议值。
- 选择自定义分辨率后，码率不再跟随。
- 自定义码率开关打开前弹出警告，确认后滑杆灰显并出现输入框，接收 1 到 500 Mbps 的整数。
- 编码格式取值为自动、H.264、HEVC、AV1；本机不支持 AV1 解码时该选项不出现。
- HDR 标注 Beta，默认关闭。编码选择 H.264 时 HDR 显示为关并灰显。
- 帧调度是最低延迟与最平滑二选一，默认最平滑。

## How to get to it (user POV)

设置页左侧选 Moonlight。分区在 General 之下，包含会话配置与下一次连接使用的配置两行只读摘要。

## Driving it with computer use

Preconditions: 标签页已由 General 分区的 Moonlight 开关打开。

读取当前取值走命令通道，写入同样走命令通道：

```sh
./.scratch/stream-cmd.sh streamSetOptions '{"resolution":"2560x1440","fps":"60","codec":"hevc"}'
```

```sh
./.scratch/stream-cmd.sh streamSetOptions '{"customBitrate":"true","bitrate":"300000"}'
```

分辨率的像素量排序、码率与分辨率和帧率的对应、自定义码率的上下限，都能由这条通道直接断言，不需要点开菜单。

菜单本身的下拉内容、滑杆的拖动手感、警告弹窗的文案属于界面呈现，需要读截图。

## 证据

| 种类 | 判据 | 谁守 |
|---|---|---|
| 结构 | 预设分辨率的排列顺序等于其像素总量升序 | `StreamOptions` 单测 |
| 结构 | 码率档位表单调递增且上界为 200 | `StreamOptions` 单测 |
| 结构 | 自定义码率的合法区间是 1 到 500 Mbps | `StreamOptions` 单测 |
| 物理 | 命令通道写入自定义码率 600000 后读到 500000 | 命令通道往返 |
| 物理 | 关闭自定义码率后码率回到档位表上的值 | 命令通道往返 |
| 物理 | H.264 下 HDR 的开状态被归一化为关 | 命令通道往返 + 截图 |
| 物理 | 选预设分辨率后码率读数变化 | 截图 + 命令通道 |
| 感知 | 滑杆拖动的手感、下拉菜单的排布 | **待做** |

## 证明的终态

进入启动单元前，设置必须落到一个主机能接受的组合：分辨率是预设或合法的自定义尺寸，帧率在四档之内，码率在滑杆或自定义区间内，编码与 HDR 不构成主机忽略的组合。

## Gotchas

- **自定义码率打开时，码率不再随分辨率或帧率变化。** 这是佩戴者接过控制权的意思，不是联动失效。
- **命令通道改分辨率不会触发码率联动。** 联动写在菜单回调里。用命令通道验证联动会得出错误结论，要改用点击菜单。
- **H.264 与 HDR 同时存储时，读出的 HDR 是关。** 归一化在读取时发生，主机在 H.264 上本来就不会送 HDR。
