# 串流输入

会话窗口捕获佩戴者的键盘与指针输入，转发给主机。输入的送达以主机的实际反应为准，不以客户端计数为准。

## Sub-features

- 会话窗口获得焦点后，键入的文字送到主机。
- 指针移动送达主机，主机的指针跟随。
- 按住不放的按键与按钮在会话结束时全部释放，不残留。
- Dock 控件释放所有按住的输入，原因为 `control-hit`。
- 输入捕获视图对画面不可见：它覆盖在视频之上，但不得遮挡视频。
- 外接手柄的按键、扳机与摇杆按 Moonlight 的报文字段转发；A/B/X/Y 各占一个位，方向键、肩键、摇杆按键、菜单键同样有位。
- 会话期间，窗口场景的每个窗口根视图挂一枚手柄事件独占，A/B/X/Y 与方向键全部只进主机。
- `StreamFocusedInputCapture` 只在窗口模式挂载：它是 `GCEventViewController` 的根视图、`UIKeyInput` 第一响应者（进场即抢、每 0.5 s 夺回、触摸时也抢），自身挂一枚手柄独占，并把键盘按键转发给主机。Dock 模式不挂载它，窗口内容整体卸载，手柄由沉浸空间的 `.handlesGameControllerEvents(matching: .gamepad)` 接收。串流画面不装输入目标与碰撞体，捏合不触发任何控件。
- 会话期间请求指针锁定：沉浸场景直接请求；窗口场景经 `prefersPointerLocked` 的窗口路由请求，只有携带会话 claim 的窗口场景满足条件。探针 `pointer lock requested` 记录请求，`none/locked/unlocked` 记录系统是否兑现。
- 手柄能力按设备实际探查后握手：控制器类型与能力位（震动、扳机震动、触摸板、加速度、陀螺仪、灯、电量）随设备变化，连接建立后重发一次到达报文。
- 回传链路：震动与扳机震动写入本机的触觉引擎，体感按主机请求的采样率上报，电量按三态与百分比每 30 秒上报一次，灯效写入控制器的指示灯。
- 手柄按键覆盖 Home、四个背键、分享键与 DualShock 触摸板按下；触摸板坐标按按下、移动、抬起三段发送，坐标按 SDL 约定归一化。
- 触摸手势层：轻点左键、双击、单指拖拽（相对或绝对，随「触摸模式」）、双指滚动、长按右键、捏合缩放；滚动走高精度接口，累计到整格时同时发传统滚轮报文。
- 鼠标侧键 X1/X2 按 Moonlight 的键码 0x04/0x05 发送；滚动累计器把高精度单位换算成传统单位。
- 「交换 ABXY」打开时会话把 A 报成 `0x2000`、B 报成 `0x1000`，X 与 Y 同理；这个交换只发生在客户端。
- 手柄连接与断开各发一次到达/离开报文；会话结束时手柄状态归零。
- 「蓝牙鼠标」默认打开；打开时会话直接转发外接鼠标的相对移动、左/右/中键与滚轮，同一时间窗口的注视与捏合指针路径被抑制，避免一次点击到达两次；关闭后交互回到注视与捏合。
- 外接鼠标的相对移动按 Moonlight 客户端的同一套映射送出：水平方向保持设备方向，垂直方向取反，两轴都除以 1.25 并保留小数余量，避免小位移被逐条丢掉。

## How to get to it (user POV)

会话进行中直接使用键盘与指针。窗口在焦点状态时输入进入会话；离开焦点后输入回到系统。

## Driving it with computer use

用 computer use 在模拟器窗口的对应位置点一下；坐标取自 `simctl io <UDID> screenshot` 的原图。

Preconditions: 会话在 streaming 状态。

键入必须走真实按键。模拟器接受的合成键盘事件与真实键入走同一条产品管线：

```sh
# 先点一下会话窗口，确认它拿到焦点
  --shot-x <x> --shot-y <y> --shot-width 3840 --shot-height 2160
osascript -e 'tell application "System Events" to keystroke "hello"'
```

送达判定读产品探针的输入计数与主机的反应：

```sh
D="$(xcrun simctl get_app_container <UDID> com.xiongzhipeng.Enchron data)/Documents"
grep "input release" "$D/stream-session-probe.log" | tail
./.scratch/stream-cmd.sh streamSnapshot '{}'   # input:keyboard=… input:mouse=… input:gamepad=…
```

手柄不依赖系统合成输入，直接走命令通道注入报文，回报同一条映射算出的位：

```sh
./.scratch/stream-cmd.sh streamSendController '{"buttons":"a"}'
./.scratch/stream-cmd.sh streamSendController '{"buttons":"a,leftShoulder","lt":"200","lx":"-32767"}'
./.scratch/stream-cmd.sh streamSendController '{"buttons":""}'   # 全零报文
```

鼠标走同一条会话入口，相对位移、按键与滚轮一次一条：

```sh
./.scratch/stream-cmd.sh streamSendMouse '{"dx":"6","dy":"-4"}'
./.scratch/stream-cmd.sh streamSendMouse '{"button":"1","down":"1"}'
./.scratch/stream-cmd.sh streamSendMouse '{"scroll":"1"}'
```

控制面 `input:mouse` 是转发入口计数；`input:hardwareMouse` 表示会话当前是否接管了外接鼠标。模拟器没有 GCMouse，真机才有。

## 证明的终态

输入的证明终点在主机一侧：主机收到了那段文字或那个指针位置。客户端计数增长只证明事件进了客户端的转发函数，不证明主机收到。

## Gotchas

- **合成键盘事件可能被系统吞掉。** 先点一下窗口让它拿到焦点，再发按键；没有焦点时事件不进会话，探针一动不动。
- **输入计数增长不等于主机收到。** 计数在转发入口就会增加。
- **手柄的交换设置属于会话快照。** 会话进行中改设置不会改这一次的映射，要等下一次启动。
- **外接鼠标接管后不要再用注视点击。** 会话抑制了手势指针路径，注视不会移动主机指针；这是为了避免鼠标点击与手势点击重复。
- **沉浸场景的普通 overlay 落在隐形宿主窗口里。** 它既不被注视也没有焦点，挂在上面的手柄独占不会被系统承认，A/B 继续被合成成 pinch；捕获视图必须作为铺满视频平面的 RealityView 附件存在，并程序化获得焦点。
- **指针锁定的兑现由系统决定。** 窗口场景的请求经窗口路由放行，但系统是否把指针锁进应用、是否隐藏光标，仍以探针三态为准；未兑现时系统光标无法从应用侧隐藏。
- **系统随航开启时，窗口模式的摇杆明显拖慢。** 实测窗口场景里手柄状态每秒只更新约 15 次，沉浸空间不受影响，约 120 次；按键只产生单次事件，感受不明显。读取手柄当前值也只得到同样的更新次数，应用侧无法补偿；关闭随航后窗口恢复正常。判断摇杆延迟前先确认随航已关闭。
- **visionOS 默认把手柄动作合成为 pinch。** 不声明手柄事件独占时，A/B 这类系统选择键被系统收走，应用与主机都收不到，同时会在注视的视图上产生一次点击；方向键不在系统选择键之列，所以看起来「部分按键正常」。
- **进入 dock 时主窗口回到活跃。** 串流窗口是从主窗口推出的，进入 dock 时串流窗口关闭，系统随即把主窗口放回并激活它；手柄事件跟随活跃场景进入主窗口，主窗口没有第一响应者捕获时 A/B/X/Y 被系统当作点击，直到佩戴者捏合 dock 画面、活跃场景移到沉浸空间。主窗口里的 1×1 捕获视图在这段时间接住手柄，使输入从进入 dock 起就送达主机；代价是 dock 串流期间手柄不能操作主窗口。
- **手柄独占按场景生效。** 窗口与沉浸空间是两个场景，只在窗口里挂独占，进入 dock 后按键又会被系统收走；沉浸空间在会话开始后才连接，独占必须跟着场景连接补挂。
- **GCMouse 给的是设备原始增量，不是屏幕位置。** 映射以 Moonlight 客户端为准：水平保持、垂直取反、除以 1.25 并保留余量。逐条四舍五入会把小位移吞掉，表现为指针发涩。
- **指针锁定同时关掉了边缘系统手势。** 没有锁定时系统指针仍会响应边缘手势，指针移动会被系统先拿去用。
- **命令通道的鼠标报文不经过方向映射。** `streamSendMouse` 直接构造主机报文，映射只在 GCMouse 入口生效。探针 `mouse delta raw=… sent=…` 是唯一能区分两者的读数。
- **滚轮的轴值没有固定量纲。** 转发按累计截断成整格，半格输入留着与后续输入合并。

## 本轮补齐范围（2026-10-26 裁决）

范围、阶段与验收见 `docs/reviews/streaming-port-review/plan.md`；本节只记这一块在本轮做什么、不做什么，避免以后又被当成遗漏。

纳入：

- 握手按设备实际探查：控制器类型与能力（震动、扳机震动、触摸板、加速度、陀螺仪、灯、电量）随设备变化；上报改到连接建立之后，失败可重发。
- 回传：震动与扳机震动、体感采样、电量周期上报、灯效写入。
- 按键：Home、四个背键、分享键、DualShock 触摸板按下；触摸板坐标按按下、移动、抬起发送。
- 缺键设备的组合补偿，以及老 MFi 手柄的定时按压补偿。
- 指针与滚轮：鼠标侧键、平滑滚动与横向滚动、窗口态的指针锁定。
- 触摸：拖拽转相对移动、双指滚动、长按右键、双击容差、缩放；在现有手势层实现，不引入上游的 Objective-C 触摸处理器。
- 设置：触摸模式与统计浮层两项随能力落地；摇杆与扳机的量化常量改成与上游一致（32766 与截断）。

不做：多手柄与本地双人、屏幕虚拟手柄、手柄退出组合键、软键盘与中文输入、键盘剩余按键与快捷键、专用蓝牙鼠标通道。这几项在能力地图里保留现状描述，不标为缺陷。

取证：新增探针行（握手、震动、体感、电量、灯效、触摸板、指针锁定）；真机在两个 gate 上验收；不新增端到端场景。
