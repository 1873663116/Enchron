# Enchron 真机 XCUI Test

本目录是 Enchron 在物理 Vision Pro 上通过公开产品界面执行 XCUI Test 的独立运作空间。这里的测试服务于同一套共享真机场景；人类验收者与自动化执行者不维护两套产品标准。

## 共享真机场景的审查与状态

现有测试方法、Test Plan 和历史结果都是审查输入，不因已经存在、被选中或曾经显示通过而自动成为当前权威回归场景。逐条说明测试要保护的用户行为、经过的公开产品入口、能够直接证明的事实、不能证明的感知条件、与其他场景的重复关系及真机执行成本。

方向明确的场景可以保留、收紧、合并或降为诊断用途。方向不明、实质删除或合并后改变产品覆盖范围时，先取得用户决定。有充分历史证据的既有场景可以恢复已经完成的人类判定校准，不要求人类为了建立新体系重新完整执行；单独的 XCTest 绿色结果不构成充分证据。

共享真机场景第一次建立可信判定时，先校准后续场景共同依赖的基础播放与输入事实，再处理空间呈现、来源、媒体组合和长时行为。场景可移交自动重复执行的部分、仍需人类判断的感知条件以及重新请求人类验收的触发条件必须明确；不存在脱离产品树、设备环境和测试媒体的永久通过状态。

## 变化后的执行范围

代码或规格变化后，根据被改变的行为、源码所有者、共享生产组件和下游产品表面选择重跑范围。Target 与源码所有权提供保守默认范围，少数跨产品表面的共享组件或平台边界补充显式关系。执行者可以依据观察到的风险扩大范围，没有直接证据时不能缩小默认范围；不为每个 Swift 文件维护一份测试方法清单。

## 无人值守完整轮换与结果结算

无人值守 Vision Pro XCTest 宿主是完成一次性系统授权与预检后，使物理 Vision Pro 保持可运行并持续执行本目录 XCTest 的测试环境。宿主可用只表示测试具备运行条件，不构成产品通过证据。

无人值守轮换回归必须尝试执行当轮选定的全部独立场景。单个场景失败、无法判断或出现可疑现象不终止整轮，也不逐条打断人类验收者；整轮结束后统一汇总产品失败、基础设施失败、未评估条件和需要人类判断的观察结果。

单条场景内部尊重第一处未满足的必要条件。已经执行的条件分别保留结果；依赖失败条件而无法执行的后续条件记为未评估。能够通过公开产品界面恢复到合法状态时继续当前场景；不能恢复时结束并清理该场景，然后继续下一条独立场景。不得通过测试专用入口绕过失败前置条件，也不得把未执行条件记为通过或产品失败。

## 人类判定校准与自动化真机执行

人类验收者负责发现现有证据尚未表达的问题，校准正确体验与失败样例，并判断机器无法可靠结算的视觉、听觉、空间和交互感受。自动化执行者负责重复执行已经明确的公开用户操作，保存规定证据，判断已经移交的机械条件，完成初步诊断，并把新的或无法判断的异常整理成短小、可直接复核的任务。

人类验收由新的或被变化触及的感知边界触发，不因某条自动测试被重跑而自动触发。提交人类复核时说明需要进入的产品状态、执行的一步操作、需要观察的具体结果和已有证据，不要求人类重复整条已机械执行的旅程。

## 动态视觉证据

本目录中的“截图验收”默认包含完整的动态取证过程，不表示只保存一个时刻的截图。XCUI Test 从场景关键操作开始前持续录制物理设备画面，直到目标状态稳定或失败边界已经出现；原始录制必须保留。执行工具按场景阶段和时间点从录制中抽取多帧，生成一张带顺序与时间信息的汇总图，使执行者先在同一视野内检查过程是否连续、状态是否遗漏以及异常大致发生在哪一段。随后对关键时刻、可疑时刻和汇总图无法可靠判断的时刻提取原始清晰帧，逐帧核对实际内容。

机械状态、连续录制、多帧汇总图和选定的原始清晰帧共同支持结论。单帧容易遗漏短暂黑帧、闪烁、重复界面、错误交接和视频内容停滞；动态场景不得只凭单帧通过。Window 与 Docked、Window 与 Panorama 的往返以及其它较长的播放场景必须使用这套取证方式。静态布局场景仍保存完整窗口清晰截图，并在交互或滚动会影响结果时同时使用连续录制和多帧汇总图。视觉录制不替代物理声音、佩戴感受或其它需要专门采集方式的证据。

## 设置驱动场景变体与真机抽样

设置项不能以菜单标题、选中状态或保存值作为最终通过。测试通过公开 Settings 改变设置，确认规定的保存边界，然后启动拥有该行为的基础场景，验证实际产品结果符合非默认设置；测试结束后使用隔离数据或恢复默认值。不同产品行为分支分别执行设置驱动场景变体。

设置驱动场景变体默认在物理 Vision Pro 上逐个覆盖全部产品选项；不能因为多个选项使用相同控件或都是数值就自行抽样。当前只有 Default Speed 的多个播放倍数允许在快速逻辑、单元或合同测试穷举全部值并证明输入映射、持久化、生产调用路径和机械语义后，按已确认的行为与风险分组选取真机边界和代表值；未进入固定样本的倍数在后续轮换中替换抽验。倍速代码路径、renderer、时间轴、媒体格式或平台边界变化时重新审查分组；代表样本失败或出现无法解释的差异时扩大真机范围。其它设置如需抽样，必须先形成新的明确决定；抽样结论不能宣称未执行值已经获得真机通过。

## 文档边界

本文件只规定本目录中的审查、协作、选择和结算方式，不复制 Enchron 产品规格、架构关系、具体场景步骤、执行命令、脚本实现或历史证据。产品事实由仓库当前规格拥有；场景目录只表达当前共享真机场景及其校准状态；机械执行由 Test Plan、测试支持代码和验证脚本拥有；运行结果由证据记录拥有。现有测试向场景目录迁移的一次性映射只写入 `MIGRATION.md`，迁移完成后删除对应记录，不能积累成第二份长期测试规范。

场景和文档保持当前状态的直接表达。风险分析只有在指向现有场景或明确缺口时保留，不维护无限扩张的可能问题目录。
