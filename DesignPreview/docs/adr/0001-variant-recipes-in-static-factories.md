# 变体配方放静态工厂,不放 DesignTokens

## Status

accepted

## 决策

DesignPreview 的**变体配方**(如「文件夹卡 = `Card` + 文件夹图标 + 数量角标」)以**标准件上的静态工厂 / 便利构造器**实现(`Card.folder(...)`、`Card.video(...)`),不以 `DesignTokens` 数据条目实现。`DesignTokens` 保持为纯数值层(圆角、颜色、间距、字号、动效),被标准件及其工厂共同读取。

## 为什么

三层分工:**DesignTokens 管值 → 标准件管结构 → 静态工厂管变体规格 → 页面只下单**。

- 变体之间的差异不止是数值,还包含**结构与内容**(角标种类、要不要缩略图)。`DesignTokens` 只能装值,装不下「这张卡有缩略图」这类结构,因此变体配方无法纯由 token 表达。
- 配方集中到一个具名实体(`Card.folder`),全仓库只定义一次;组件库陈列它、DesignComps 页面复用它,改一处全仓库变。这正是「DesignComps 只调标准件改参数、不复制代码」铁律的落地前提——避免配方降级成参数级复制。

## Considered Options

- **裸参数派**(每个页面手写整套参数):角色塌缩了,但配方在每个调用点重复 → 参数级复制,绕过铁律。否决。
- **DesignTokens 预设派**(配方塞进 token 数据):装不下结构差异,且把「值」层污染成「配置」层,混层。否决。

## Consequences

- 每个变体需要一个规范名(中英双名,见 `CONTEXT.md`),这是一次性术语成本。
- 组件库的陈列项从「多个 struct」变为「同一标准件的多个具名工厂实例」。
- 未来若有人(或 Agent)试图把变体配方塞回 `DesignTokens`,以本 ADR 否决。
